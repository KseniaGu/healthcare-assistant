# CA1 training recipe and environment

The maintained trainer consumes only an accepted self-contained CA1 packet. It is research-only; no adapter is deployed to the application. [Reproduction](../reproduction.md) holds operational commands, including later manual VM steps.

The comparison recipe uses Qwen/Qwen3-4B-Instruct-2507 at revision `cdbee75f17c01a7cc42f958dc650907174af0554`, one NVIDIA L4, BF16, NF4 with double quantization, and LoRA rank 16/alpha 32/dropout 0.05 on all linear layers. It trains three epochs with microbatch 1, accumulation 8, AdamW weight decay 0.01, cosine schedule, learning rate 1e-4, warmup 4, and seed 42. Validation runs at steps 40/80/120; checkpoints save every 10 steps. The packet limit is 8,192 complete chat tokens with assistant-only labels. The longest-example `preflight` performs one forward/backward pass without a weight update. `check` verifies the packet offline without model loading.

The local `pyproject.toml` plus tracked `poetry.lock` define the reproducible development and dataset-generation environment. The optional `research` group pins Transformers 5.16.1, tokenizers 0.23.2, and Torch 2.14.0 for offline checks. The cloud L4 uses [requirements-training.txt](requirements-training.txt) for its separate pinned research stack and must retain its known-good CUDA PyTorch installation (historically 2.8.0+cu128). Poetry must not replace the VM's CUDA Torch. A package or hardware change is a recorded deviation.

The historical Lightning L4 run completed 120 optimizer steps in 4,990 seconds with 14.18 GiB peak allocated. Synthetic validation loss selected checkpoint 80 (step losses 0.01391129/0.01355948/0.01509854). The original selected-adapter archive SHA-256 is `e880cf8637d8df52f80a0073f0922ea176fd4d4fa5db56bef85ad621893f2344`; it supports inference but not optimizer-state resumption. The original separate Studio input archives are the run's provenance; a unified archive was assembled afterward. See [historical evaluations](../evaluation/historical_evaluations.md) for scores and private artifact links.

A new run records packet content digest, source commit, package/hardware versions, full recipe, validation losses, selected checkpoint, and completion status in `run.json`. Resume requires the same packet, recipe, complete checkpoint under the same output directory, hardware, and dependencies. Preserve optimizer, scheduler, and RNG state for resume. Cloud training and matched evaluation of the refactored packet remain manual procedures.
