# CA1 training recipe and environment

The maintained trainer consumes only an accepted self-contained CA1 packet. It is research-only; no adapter is deployed to the application. [Reproduction](../reproduction.md) holds operational commands, including the manual VM steps.

The comparison recipe uses Qwen/Qwen3-4B-Instruct-2507 at revision `cdbee75f17c01a7cc42f958dc650907174af0554`, one NVIDIA L4, BF16, NF4 with double quantization, and LoRA rank 16/alpha 32/dropout 0.05 on all linear layers. It trains three epochs with microbatch 1, accumulation 8, AdamW weight decay 0.01, cosine schedule, learning rate 1e-4, warmup 4, and seed 42. Validation runs at steps 40/80/120; checkpoints save every 10 steps. The packet limit is 8,192 complete chat tokens with assistant-only labels. The longest-example `preflight` performs one forward/backward pass without a weight update. `check` verifies the packet offline without model loading.

The local `pyproject.toml` plus tracked `poetry.lock` define the reproducible development and dataset-generation environment. The optional `research` group pins Transformers 5.16.1, tokenizers 0.23.2, and Torch 2.14.0 for offline checks. The cloud L4 uses [requirements-training.txt](requirements-training.txt) for its separate pinned research stack and must retain its known-good CUDA PyTorch installation (2.8.0+cu128 for the recorded run). Poetry must not replace the VM's CUDA Torch. A package or hardware change is a recorded deviation.

The accepted v3 run completed manually on 2026-10-05: one L4, PyTorch 2.8.0+cu128, Transformers 5.16.1, tokenizers 0.23.2, PEFT 0.21.0, Accelerate 1.15.0, bitsandbytes 0.50.2, and W&B 0.30.0. The longest-example preflight passed at 4,742 tokens and 16.33 GiB peak allocation. Training completed 120 optimizer steps in 5,018.4 seconds with 14.18 GiB peak allocation. The step-40/80/120 validation losses were 0.01320839, 0.01335769, and 0.01515837; the lowest selected `checkpoint-40`. The [W&B record](https://wandb.ai/gu-fuku-ro-/ca1-pilot-v3/runs/qra140m7) and private [selected-adapter archive](../../../data/research/extraction/ca1-selected-adapter-v3.tar.gz) (SHA-256 `2ba47d57c91c8f9dfd93ea414af4ae335d250e6116373ce41f4a13fc270b7924`) preserve the completed run record, adapter config, and 504-tensor safetensors file. Its recorded trainer-source hash matches the committed trainer. The [evaluation](../evaluation/evaluations.md) reports the matched outputs and case-level limitations.

Preflight and training reject staged or unstaged tracked repository changes before CUDA use; `check` remains an offline packet check. `run.json` records selected recipe settings, packet digest, source commit, trainer-file hash, package/hardware versions, validation losses, selected checkpoint, and completion status. The clean commit and trainer hash identify executable settings that are not repeated as individual recipe fields. Each update replaces `run.json` atomically, preserving the previous complete record if writing is interrupted. Resume requires the same packet, recipe, complete checkpoint under the same output directory, hardware, and dependencies. The downloaded selected-adapter archive supports inference, not optimizer-state resumption; the full optimizer, scheduler, RNG, and checkpoint history remains to be copied if later resume or full archival is required.
